# Before you install

Unofficial firmware changes the software inside your camera. Volunteers develop and test these mods on their own cameras, without earning money from the work. They can tell you what happened on theirs. Nobody can guarantee what will happen on yours.

**Expect bugs.** A camera can keep restarting (a boot loop), show a black screen or stop starting altogether. You could lose photos or settings, and a modification may affect your warranty. You accept the risk. Neither the Atlas nor the linked projects accept responsibility for damage to your camera. If you need a guarantee, keep the official firmware.

## Check the match

1. Find [your exact camera](../views/cameras/index.md). Check the generation and the firmware version in its settings.
2. Open the project from that camera's page. Read its installation guide and warnings for the **specific release**. A project covering several cameras may only have a download for one.
3. Look for a real camera report for that build. A release means a file is available. A test in an emulator (a computer simulation of the camera) answers a different question. [How to read the evidence](evidence.md).
4. Back up photos and settings you need. Find the project's recovery instructions and obtain the correct official firmware before starting. Follow the project's directions for the card, battery, controls and completion signal. If the model, file or instructions are unclear, stop before installing.

## If the camera will not start

Some cameras can still read an update from the memory card when their normal menus will not open. Recovery means **reinstalling the official camera software**. In general, you prepare a card with the official file for that exact model, using the folder and filename specified in its guide. You start the camera in its card-update mode and follow the guide through completion before removing power or restarting.

Recovery depends on the camera still being able to run the updater. A blank screen alone cannot tell you whether it is updating. Use the model-specific instructions and ask the project if the indicators differ. **Card recovery is not guaranteed.**

## What owners have reported

- **OM-5 Mark II.** The Caduceus project records five development builds that failed on the owner's camera. The owner restored official firmware from the card each time. A later development package also produced an intermittent restart loop whose cause remained unknown. [Project history](../views/projects/caduceus-om5.md) · [Development package report](../views/evidence/om5-ii-dev0565-boot.md).
- **Olympus PEN E-PM2.** EPM2Mod records five failed builds recovered by a normal card update. The project has no recorded recovery from a boot loop on this body. [Project history and install guide](../views/projects/epm2mod.md) · [Owner's camera report](../views/evidence/epm2-films-look-exif.md).

The type of change matters too. A fault during start-up can affect every attempt to switch on. A fault in a shooting feature may only appear when you use it. Even a change described as a menu or colour feature can involve start-up code. [How projects change the camera](cross-body.md#risk-by-type-of-change).
